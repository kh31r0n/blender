# Task: Generate a Complete 3×3-Block LEGO City Neighborhood in Blender Using the Existing "Edificio LEGO" Geometry Nodes Generator

## Objective

Build a complete, visually varied LEGO-style city neighborhood of **3 × 3 city blocks** in Blender. Populate it with many different buildings generated by the project's existing Geometry Nodes group **"Edificio LEGO"**.

The focus of this task is **varied buildings**: different heights, widths, depths, ground floors, roofs, colors and random variation, arranged into a believable neighborhood with a clear skyline. Streets are only empty space between the blocks, on a plain ground surface.

**Reuse the existing generator. Do not create a new building generator, do not modify the "Edificio LEGO" node group or its generator script, and do not model or import buildings by hand.** Every building must be an object with its own Geometry Nodes modifier that uses "Edificio LEGO", configured through the modifier inputs.

## 3. The "Edificio LEGO" Generator — Reference

### Modifier inputs

The inputs use exact Spanish names. Use these names to look up the identifiers.

| Input | Type / range | Meaning |
|---|---|---|
| `Pisos` | int, 1–100 (default 6) | Total floors, including the ground floor. |
| `Ancho (studs)` | int, 8–96 (default 16) | Footprint along local X. Odd values are allowed. |
| `Fondo (studs)` | int, 8–96 (default 12) | Footprint along local Y. |
| `Planta baja` | menu | `Entrada hotel` (double door if `Ancho ≥ 14`, plus a black canopy), `Puerta simple`, `Escaparates` (tall shop windows and a door) or `Sin puerta`. |
| `Remate` | menu | `Alero con pináculos` (Nitro-style black eave, lattice fence and pinnacles), `Cornisa plana` (flat cornice with parapet) or `Azotea` (flat tiled roof). |
| Variación › `Semilla` | int | Seed for blind window columns, flower boxes and lit windows. |
| Variación › `Ventanas ciegas` | factor 0–1 (default 0.15) | Probability that a window column is bricked up. |
| Variación › `Jardineras` | factor 0–1 (default 0.3) | Probability of a flower box under each window. |
| Variación › `Luces encendidas` | factor 0–1 (default 0) | Probability that a window uses the lit-glass material. |
| Marquesina › `Ancho marquesina (studs)` | int, 8–40 (default 12) | Hotel canopy width. The generator clamps it to the building. |
| Marquesina › `Vuelo marquesina (studs)` | int, 3–12 (default 4) | How far the hotel canopy projects. |
| Marquesina › `Altura marquesina (placas)` | int, −3–6 (default 1) | Vertical offset of the canopy. |
| Marquesina › `Pináculos superiores` | int, 0–12 (default 3) | Number of top finials on the canopy. |
| Marquesina › `Separación pináculos (studs)` | int, 0–12 (default 0 = automatic) | Spacing of the top finials. |
| Colores › `Pared`, `Marcos`, `Vidrio`, `Vidrio encendido`, `Molduras`, `Tejado`, `Azotea`, `Detalles`, `Puerta`, `Plantas`, `Flores`, `Pendientes marquesina` | material | Material for each role. |
| `Realizar instancias` | bool (default False) | **Keep it False.** Buildings must remain instances. |

The canopy inputs only have an effect with `Planta baja = Entrada hotel`.

### Geometry facts

You must confirm these in step 3 of section 2.

- **Origin:** the object origin is at the **center of the footprint, at ground level** (z = 0).
- **Front facade:** the front faces **local −Y**. That is where the door, the hotel canopy and the shop windows go. The other three facades only have windows.
- **Overhangs outside the footprint:**
  - The `Alero con pináculos` and `Cornisa plana` roofs project **1 stud** beyond the footprint on all four sides.
  - Flower boxes project **1 stud** on every facade.
  - With `Entrada hotel`, the canopy projects **`Vuelo marquesina` studs** (default 4) in front of the front facade.
- **Envelope:** for layout purposes, take a building's envelope to be its footprint grown by 1 stud on every side, plus `max(1, Vuelo marquesina)` studs on the front if it is a hotel.

### Blender 5.2 API pitfalls (verified in this project)

- **Setting modifier inputs:**
  - `mod["Socket_N"] = v` **does not work** in Blender 5.x.
  - Use `getattr(mod.properties.inputs, identifier).value = v`. Get the identifier from `node_group.interface.items_tree` by matching the input name.
  - **Menu inputs** take the item name as a string, for example `"Escaparates"`.
  - **Material inputs** take a `bpy.types.Material`.
- **Re-evaluation:** after changing inputs, call `ob.update_tag()` and then `bpy.context.view_layer.update()` before evaluating. Otherwise the depsgraph returns stale results.
- **World nodes:** `World.use_nodes` is deprecated. New worlds already have a node tree.
- **Video output** (only if you render one): set `scene.render.image_settings.media_type = 'VIDEO'` before `file_format = 'FFMPEG'`.
- **Instance cost:** buildings are instances. A 40-floor 32×32 building is about 16,000 instances, which is cheap. Realized, the same building is about 5.8 million vertices. Never realize instances.

## 4. Neighborhood Layout

### Grid

- **Blocks:** 3 × 3, each **32 × 32 studs** (25.6 BU, the size of a LEGO baseplate).
- **Streets:** **16 studs** (12.8 BU) wide, both between blocks and as a ring road around the whole neighborhood.
- **Total area:** 3·32 + 4·16 = 160 studs = 128 BU per side, centered on the world origin.
- **Block centers:** at x, y ∈ {−38.4, 0, +38.4} BU. Each block spans ±12.8 BU from its center.
- **Naming:** blocks `A1`…`C3` (rows A–C from south/−Y to north/+Y, columns 1–3 from west/−X to east/+X).

### Stud alignment

- Every building footprint edge must lie on the **stud grid of its block**: `block_min + k × 0.8` with integer k.
- For an unrotated building, `location.x = x_min + Ancho × 0.4` and `location.y = y_min + Fondo × 0.4`. Account for the 90° swaps when the building is rotated.
- Rotate only around Z, in multiples of 90°. The front (local −Y) must face a street:

| Front faces | `rotation_euler.z` |
|---|---|
| South (−Y) | 0° |
| East (+X) | +90° |
| North (+Y) | 180° |
| West (−X) | −90° |

### Lots

- **Envelopes inside the block:** every building's envelope (section 3) must lie inside its block. The **only exception** is the hotel canopy, which may project into the street by up to 4 studs.
- **No overlaps:** envelopes of different buildings must not overlap. Neighbors may be separated by exactly their envelopes (a 2-stud gap between footprints) or more.
- **Facing streets:** buildings line the block edges facing the streets. Corner lots may face either street. Block interiors may stay empty as courtyards.
- **Lots per block:** 2–4 buildings per block. Aim for **22–32 buildings in total**.

## 5. Building Variety

### Archetypes

Use at least these five. Ranges are guidelines; vary within them.

| Archetype | Pisos | Ancho × Fondo (studs) | Planta baja | Remate | Count |
|---|---|---|---|---|---|
| Hotel tower (landmark) | 10–16 | 16–20 × 12–16 | `Entrada hotel` | `Alero con pináculos` | 1–2, central block |
| Apartment building | 5–9 | 12–16 × 10–14 | `Puerta simple` | `Cornisa plana` or `Alero con pináculos` | about 30% |
| Shop with flats above | 3–5 | 10–14 × 10–12 | `Escaparates` | `Cornisa plana` | about 30% |
| Narrow townhouse | 2–4 | 8–10 × 10–12 | `Puerta simple` | `Azotea` or `Cornisa plana` | about 25% |
| Office block | 6–12 | 16–24 × 12–16 | `Escaparates` | `Azotea` or `Cornisa plana` | 2–4 |

Use `Sin puerta` sparingly, at most 10% of buildings, and never on a building whose front faces a main street.

### Skyline

- The **central block (B2)** holds the tallest building: the hotel landmark, in the Nitro style.
- Heights decrease toward the corner blocks, with local variation so that the neighborhood does not look like a staircase.
- No more than two buildings in the whole neighborhood may share the same `Pisos` value and the same archetype.

### Color schemes

These exact material names exist; verify them anyway. Each scheme lists `Pared` / `Molduras` / `Tejado`; for `Azotea`, `LEGO 199 Dark Bluish Grey` or `LEGO 194 Light Bluish Grey` work with any scheme.

| Scheme | Pared | Molduras | Tejado |
|---|---|---|---|
| Nitro hotel | `LEGO 1 White` | `LEGO 1 White` | `LEGO 26 Black` |
| Sandstone | `LEGO 5 Tan` | `LEGO 138 Dark Tan` | `LEGO 138 Dark Tan` |
| Red brick | `LEGO 154 Dark Red` | `LEGO 5 Tan` | `LEGO 199 Dark Bluish Grey` |
| Brown brick | `LEGO 192 Reddish Brown` | `LEGO 194 Light Bluish Grey` | `LEGO 26 Black` |
| Sand green | `LEGO 151 Sand Green` | `LEGO 1 White` | `LEGO 199 Dark Bluish Grey` |
| Sand blue | `LEGO 135 Sand Blue` | `LEGO 1 White` | `LEGO 140 Dark Blue` |
| Nougat | `LEGO 283 Light Nougat` | `LEGO 312 Medium Nougat` | `LEGO 192 Reddish Brown` |
| Olive | `LEGO 330 Olive Green` | `LEGO 5 Tan` | `LEGO 26 Black` |
| Grey office | `LEGO 194 Light Bluish Grey` | `LEGO 199 Dark Bluish Grey` | `LEGO 199 Dark Bluish Grey` |

Rules for color:

- Doors (`Puerta`): `LEGO 192 Reddish Brown`, `LEGO 154 Dark Red`, `LEGO 140 Dark Blue`, `LEGO 28 Dark Green` or `LEGO 26 Black`.
- Window frames (`Marcos`) stay `LEGO 1 White` unless the scheme needs contrast.
- Glass (`Vidrio`) stays `LEGO 375 Trans Smoke`.
- **No two adjacent buildings** (same block, or facing each other across a narrow gap) may share the same `Pared` material.
- Use each scheme at least once, and none more than 5 times.

### Random variation

- **Seeds:** every building gets a unique `Semilla`, derived deterministically from one master seed in the script.
- **Ranges:** `Ventanas ciegas` 0.0–0.3, `Jardineras` 0.1–0.5, `Luces encendidas` 0.0 (daytime).
- **Uniqueness:** no two buildings may have identical parameter sets.

## 6. Scene Setup

- **Example buildings:** in the **new** file, delete the objects `Hotel`, `Tienda` and `Casa`. Keep the "Piezas LDraw" collection exactly as it is.
- **City collection:** create a collection `Ciudad` with one child collection per block (`Manzana_A1` … `Manzana_C3`). Name buildings `<block>_<nn>_<archetype>`, for example `B2_01_Hotel`.
- **Building objects:** each building is an object with an empty mesh and one Geometry Nodes modifier using "Edificio LEGO". Store the archetype, the block and the lot as custom properties.
- **Ground:**
  - Replace or resize `Suelo` to cover the full 128 × 128 BU area plus a margin, using `LEGO 199 Dark Bluish Grey` (streets).
  - Add one flat block pad per block (32 × 32 studs, `LEGO 194 Light Bluish Grey`, top surface at z = 0).
  - Keep the street ground slightly lower (z = −0.01) to avoid z-fighting.
  - No street details: see section 11.
- **Lighting:** reuse `Sol` and `Cielo`. Keep the sun angled so that building faces are clearly modelled.
- **Cameras** (add the named ones as separate objects):
  - `Camara`: aerial three-quarter overview of the whole neighborhood. This is the scene camera.
  - `Cam_Planta`: top-down orthographic plan.
  - `Cam_Calle_1`, `Cam_Calle_2`, `Cam_Calle_3`: street-level views (eye height about 1.8 BU, a minifigure's eye level) along three different streets.
  - `Cam_Centro`: close-up of the central block.
- **Render settings:** EEVEE, AgX, 1920 × 1080.

## 8. Validation

Validate the actual Blender result, not just that the script runs without errors.

### Structural checks

Print a report covering all of the following:

- **Evaluation:** for every building, `mod.node_warnings` is empty and the evaluated instance count is greater than 0.
- **Real extents:**
  - For each building, iterate `depsgraph.object_instances`, keep instances where `inst.is_instance and inst.parent.original == building`, and take the world-space bounding box from `inst.matrix_world` applied to the bounding box of `inst.object.data`.
  - Check that no two buildings' XY boxes overlap (tolerance 0.01 BU).
  - Check that every box lies inside its block, except hotel canopies, which may extend at most 4 studs into the street.
- **Orientation:** every building's front faces a street, and every footprint is aligned to the stud grid.
- **Variety rules:** the counts per archetype, the color-adjacency rule, unique seeds and unique parameter sets.
- **Totals:** the total instance count (keep it under about 80,000) and the evaluation time.
- **Reopen test:** open the saved file in a **fresh** Blender process, re-evaluate it, and confirm that the building count and the total instance count match.

### Visual checks

- Render all six cameras with EEVEE into `~/blender/buildings/renders/ciudad_3x3/`.
- **Open and inspect every image.** Check the skyline, color variety, repetition, gaps or collisions between buildings, buildings facing the wrong way, and anything floating or clipped.
- Fix problems and render again. Repeat until the result meets the acceptance criteria.
- **Do not claim visual validation unless you actually looked at the rendered images.**
